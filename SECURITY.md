# Security policy

Only the latest Rumi beta is supported with security fixes. An installation failure, data loss, or credential leak blocks a public release.

## Report privately

Use [Report a vulnerability](https://github.com/linshenghou/Rumi/security/advisories/new) on the Rumi repository. Private vulnerability reporting is enabled on this repository; maintainers verify the channel before each release. If GitHub does not offer that form, do not open a public issue containing sensitive details. Wait until a working private channel is announced.

Include the app version, macOS version, impact and minimal reproduction using synthetic data. Never include a live API key, a private paper, or an unredacted home directory. Revoke exposed credentials with the API provider; deleting an issue or Git commit does not revoke a key.

Please allow maintainers to investigate and coordinate a fix before public disclosure. Beta support is best effort; no response-time SLA is promised. Ordinary, non-sensitive bugs belong in [Issues](https://github.com/linshenghou/Rumi/issues).
